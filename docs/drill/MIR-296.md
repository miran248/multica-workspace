# Drill spec — the reslice window and one PR link

Throwaway record for the MIR-289 live-acceptance drill in a throwaway project.

The reslice window is the spec PR unmerged, or merged with no child in a started status: a
change inside it is made in place, at the same PR number and head. The slice freezes at the
first started child; a real change after that is a new epic.

Revision inside the window: the changed direction is amended at the same head and PR number;
the child set is rewritten in place, never duplicated. After the approval merge, the same spec
child is reopened at `spec_progress` and one revision PR targets `spec/MIR-295`; every child of
the revised set exists before that PR is reviewed, and its fresh PASS and merge re-approve the
revised set. No second epic is opened.

The freeze is a latch, not a current-status test: a started child is anything but `backlog`,
`todo`, `done` or `cancelled`, and once the condition has held it holds for the rest of the
slice's life. `done` is not a started status, but a done child cannot exist before the freeze,
so a delivered slice stays frozen; a `blocked` child was promoted and counts as started.
