name: domain-modeling
description: "Resolve domain terminology or conceptual interface boundaries when terms, invariants or relationships need a decision."
metadata:
  version: 0.1.0-pilot.1
---

Read the project's glossary, context map and relevant ADRs. Compare proposed terms and relationships with actual behavior and accepted decisions. Use concrete edge cases to reveal ambiguous ownership, identity, lifecycle, or invariants.

Propose precise canonical terms and interface responsibilities; explain meaningful alternatives with evidence. Ask only unresolved consequential choices. Record settled domain meanings in the existing glossary format, keeping implementation detail in design notes. Record an ADR when a consequential tradeoff would otherwise be surprising and costly to reverse. Use the project's vocabulary rather than imposing a new universal naming scheme. Finish with a coherent model, tested examples, and explicit unresolved decisions.
